## 6.2 `00_梳理总览与目录对照.md` 的「成书过程」一节

> 00 是这本书的说明书：它是什么、怎么做的、还剩什么问题。**看完这一节，不必翻别处就能判断这本书能不能用。**

### 6.2.1 定位

- **文件名**：`<书名>00_梳理总览与目录对照.md`（带书名+卷册前缀，与其余四件一致）
- **位置**：交付目录 `<书名>/`
- **生成方式**：assemble 生成骨架（页码体系、目录↔页码对照）→ 执行者补写成书过程一节
- **补写落点＝`work/00_after.md`**：写这个文件，不要手改 00。assemble 每轮整篇重写 00，手写内容会被抹；而装配期已把「`work/00_after.md` 存在即追加到 00 末尾」做成固定环节，且追加在交付指纹计算**之前**，所以指纹天然包含它（两路径同口径，见 SKILL §3E「组装」与 §6.2）。
- **不内嵌改错留痕**：只引用 `04_改错留痕.md` 并附摘要（总条数 / 通改数 / 逐页明细数），细节在 04

### 6.2.2 成书过程三节（缺一不可）

| 节 | 标题 | 写什么 | 数据来源 |
|----|------|--------|---------|
| 一 | 关键判断 | 底本类型与页码体系怎么定的；结构清洗做了哪些（剥书眉 / 表审计 / 碎片剥离 / 简繁扫描）；有无形态特殊之处（整页图、批注夹注、多套页码） | `book_meta.json`、`page_index.json`、`table_audit.md`、`region_noise_audit.md` |
| 二 | 派工概况 | 分章方案（章范围 / phys / 字符数 / 补丁数）；各组产出；合并校准中的主要问题 | `reading_progress.md`、`notes/*.md`、`corrections/*.json` |
| 三 | 收尾结论 | 闸A 抽检清单的处置（哪几页读过、哪些列为疑似、改了还是放行）；闸B 差异的裁决；已知遗留问题 | `gate_report.md`（闸A 抽检清单 / 闸B 差异 / 交付完整性三项结论，check_book 落盘）、`audit_report.md`（assemble 流程数据 15 字段）、`correction_miss_log.md`、`patch_manifest.json` |

**存疑项自动汇总**：`corrections/*.json` 中 `type=存疑` 或 `reason` 以"存疑"开头的补丁，自动提取成表（来源 / phys / 原文 / 存疑说明），列入第三节。

**数字口径统一**：补丁总数、active/deleted 计数与 `patch_manifest.json` 最终态一致；新增或撤销补丁后须回写本节数字，不得前后不一致。

## 6.3 `04_改错留痕.md` 规范

> 04 是这本书的账本：每个字为什么改、第几页改了什么、撤销了哪些。**拿着 03 的某一页，必须能在 04 里查到这一页发生过什么。**

**生成方式：台账主源 + diff 兜底**（由 `gen_correction_ledger.py` 产出）
- **主源**：从 `patch_manifest` 中 `status=active` 的补丁逐条取 `old/new/类型/依据/来源`。
- **兜底**：`diff(最终 03 干净文本, 原始 pristine 文本)` 发现台账遗漏的改处并报警——**用 diff 找漏，不用 diff 生成清单**（纯 diff 会把剥书眉 / 加锚 / 结构清洗当"改错"）。
- **只列真改过的**：`old` 在底本 0 命中的预防性登记不入 §一——那不是"改了几处"，是"准备了但没用上"，会把真正发生过的改动淹没；这类 0 命中补丁在 §三 单独汇总（不与真改动混数）。
- **派生件同步**：notes / 00 / 02 等派生件随台账修订同步的情况记 `derived_sync_log.json`（§四 4.3 引用），防"台账改了、派生件没跟着改"。
- **纠错类型十二类细分表**（§一按类型分组用）：形近字 / 义校 / 专名 / 书名号 / 数字标点 / 衍字删除 / 跨页断词 / 曰日混用 / 繁简转换 / 多命中特异化 / 人工修订 / 其他——类型取自补丁 `type` 字段，归一后入组。

**§一 通改总清单**：按类型分组（形近字 / 义校 / 专名 / 书名号 / 数字标点…），合并同 `old→new`，标注命中页数与补丁来源文件；同一 `old→new` 只出现一次。

**§二 逐页明细**：按 `<<<PAGE phys=N book=M>>>` 排序，每页列该页所有改动：`原OCR「X」→ 改「Y」（类型 + 依据 + 补丁来源）`。**这一节是"翻到某页查改了什么"的主体，不压缩、不抽稀。**

**§三 一致性自校验**：
- §一所列 `old` 在 03 干净正文残留 = 0；
- §一所列 `new` 在 03 干净正文命中 > 0；
- 条数 = active 补丁条数 + diff 发现数；
- diff 发现的"台账遗漏改处"单独列出并报警；
- 结论：通过 / 未通过（未通过列差异）。

**§四 撤销与人工修订**：两类各一行一条
- 经核实撤销的补丁：`phys / 原补丁 old→new / 撤销理由 / 核实方式`；
- 修订路径下的人工定点修订：`phys / 原文 / 改为 / 理由`。

> 撤销也是改动，与改错同记一本账，才能"翻到某页就查到这页发生过什么"。

**预处理处置登记（v2.1.0 立 · v2.2.0 接线为 4.4）**：00b/00c/00d/00e 发现的问题，处置结果在此登记。**v2.2.0 起权威源是 `work/04_dispositions.md`**：该文件存在即由 `gen_correction_ledger.py` 整体并入 04 §四作为 **4.4「考据裁定与预处理处置登记」**（置于 4.3 之后，走 `safe_write`：LF/原子/备份）——考据裁定（为何某处不修）、预处理红旗项处置、不阻断遗留都记在源文件里，**无需手工贴 04**（历史上手工贴补每轮被 assemble 冲掉、文本模式写盘把全文转 CRLF、描述词形被卫生检查擒，三连坑）。源文件即 4.4 正文：自由 Markdown，小节标题用 `####`（勿与 `###` 冲突），勿写文件级大标题；该节被 `check_book` 豁免占位符扫描与人工修订解析（`load_manual_revisions` / `check_file_hygiene`），描述性引用词形安全。文件不存在时 04 记「无」并提示可直接记于该文件。`check_book.py` 预处理闭环检查仍通过关键词识别，不依赖节号。

| 预处理环节 | 登记内容 | 示例 |
|-----------|---------|------|
| 00b 表格审计 | 空td>30% 红旗表的处置：LLM重建 / 原图兜底 / 确认保留 | `phys=114：3列拆成14列，LLM重建HTML；phys=104：音标表结构正确，保留原图兜底` |
| 00c 碎片剥离 | 是否 --apply；剥离页数；整页排除页的处置 | `已 --apply，剥离12页碎片；phys=15整页排除（图例表）` |
| 00d 图片缺口 | A类断链补图 / C类文字层确认原图已嵌入 | `A类0个；C类2个，确认 book_ocr 裁图已嵌入 imgs/` |
| 00e 简繁抖动 | 通改候选入补丁 / 确认保留 / 逐字判 | `通改候选3字：「云→雲」入 systematic；「后→後」确认底本惯例保留` |

> 设计意图：预处理环节跑了就忘是 2.0.0 之前的设计缺陷——报告落在 work 目录，Stage 3 精读时注意力被文字吸走，再也没人回头看。v2.1.0 起：assemble 自动把预处理审计汇总进 00 §五，check_book 自动检查红旗项是否在 04 有处置登记，两者都是报告项、不阻断。

**§五 交付指纹**（assemble 定稿前追加，`pipeline_assemble.py` / `assemble_epub.py` 同构）：
- 记 00/01/02/03 的 sha256，格式 `00=sha256:<64hex>；01=…；…`；
- **为什么用哈希不用 mtime**：work 与交付目录常在 OneDrive 内，同步会刷新 mtime，mtime 判据认不出「内容被换过」；
- 指纹用于**确认交付件与 04 记录同源**。修订路径下改了 03，就在 §四 登记并更新指纹——指纹是留痕工具，不是拦下改动的闸。

**corrections 台账完整性保护（patch_manifest.json）**：
- `.work` 被 gitignore，git 查不到删除史。台账全历史可追溯，不依赖 git。
- **自动索引**：`gen_patch_manifest.py` 扫描 `corrections/*.json` 生成 `patch_manifest.json`（含 `status` 字段）；不人工维护第二份真相源。
- **删除登记**：删除走「核实 → 04 §四 登记 → 标 `deleted`」三步，不物理删；assemble / 闸B 只处理 `active`。标 deleted 有两个位置：① corrections 单条 `status=deleted`（活文件为准，优先）；② 在 `patch_manifest.json` 按 id 手标（兼容旧工作流）。
- **id 口径（v2.2.0）**：内容键 = `源文件名#sha1(old|new|phys)[:10]`（`_common.patch_stable_id` 单一真相源，同文件重复内容加 `#2/#3` 出现序）。**不随条目增删/文件重生成漂移**——历史方案「文件名#下标」在下标平移时把墓碑误标到另一条 active 补丁上（实测误杀：一本书 8 处残留中 2 处、全库 4 本 1036 条状态相左）。legacy（下标式）manifest 的墓碑按 `(source, old, phys)` 内容自动迁移；内容暂不在 corrections 的墓碑转入 `orphan_tombstones`，复现时自动生效。**改 corrections 后无需任何手工 manifest 操作**，重跑 `gen_patch_manifest.py` 即自动对账。

## 6.4 图版嵌入工具链（PDF + EPUB 两条路径）

**整页图版嵌入**（`06_embed_pdf_figures.py` / `06b_embed_epub_figures.py` / `06c_embed_epub_slice_figs.py`）：EPUB 从 zip 解内嵌 `<img>`、PDF 从图版页渲染提图。三工具均**纯插入、零改写**——不动原页任何文字，只在 03 对应位置插图片引用行；写盘统一 LF、自动备份、幂等（已嵌入即跳过，由 `test_06b_apply.py` / `test_06c_apply.py` / `test_07c_idempotent.py` 回归守着）。**图落点统一收敛（2026-10-19）**：06/06b 落 03 同层 `fig/` 子目录（引用 `fig/fig_….jpeg`），06c 落 `imgs/`（引用 `imgs/fig_….jpg`）——一律带目录前缀，与 07c（`fig/fig_pNNNN_k.png`）同口径，`check_book.py` 断链核验（只认 `imgs/`·`fig/` 前缀）全覆盖，不留核验盲区。

**正文内嵌图版**（`07_probe_page_figures.py --pdf <pdf> --out <dir>` → `07e_figcrop_refine.py --pdf <pdf> --out <dir>` → `07b_classify_figures.py --probe <json> --figdir <dir> --out <json>` → `07c_embed_figures.py --pdf <pdf> --md <03> --probe <json> --classify <json> [--apply]`）：补整页图版覆盖不到的另一半——图与正文同页、图幅只占页面一块，且**无图号也能自动找图**。整页扫描型 PDF 尤其需要。

> 路径三（PaddleOCR 三件套）跳过本节工具链——book_ocr 三件套本身已含图版，复用已嵌裁图即可。

**技术实现细节**：补丁施加器匹配与让位机制（`apply_corrections_core`）、共享口径单一真相源（`_fig_common.py`）见对应脚本注释。

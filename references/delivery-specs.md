## 6.2 `00_梳理总览与目录对照.md` 的「成书过程」一节

> 00 是这本书的说明书：它是什么、怎么做的、还剩什么问题。**看完这一节，不必翻别处就能判断这本书能不能用。**

### 6.2.1 定位

- **文件名**：`<书名>00_梳理总览与目录对照.md`（带书名+卷册前缀，与其余四件一致）
- **位置**：交付目录 `<书名>/`
- **生成方式**：assemble 生成骨架（页码体系、目录↔页码对照）→ 执行者补写成书过程一节
- **不内嵌改错留痕**：只引用 `04_改错留痕.md` 并附摘要（总条数 / 通改数 / 逐页明细数），细节在 04

### 6.2.2 成书过程三节（缺一不可）

| 节 | 标题 | 写什么 | 数据来源 |
|----|------|--------|---------|
| 一 | 关键判断 | 底本类型与页码体系怎么定的；结构清洗做了哪些（剥书眉 / 表审计 / 碎片剥离 / 简繁扫描）；有无形态特殊之处（整页图、批注夹注、多套页码） | `book_meta.json`、`page_index.json`、`table_audit.md`、`region_noise_audit.md` |
| 二 | 派工概况 | 分章方案（章范围 / phys / 字符数 / 补丁数）；各组产出；合并校准中的主要问题 | `reading_progress.md`、`notes/*.md`、`corrections/*.json` |
| 三 | 收尾结论 | 闸A 抽检清单的处置（哪几页读过、哪些列为疑似、改了还是放行）；闸B 差异的裁决；已知遗留问题 | `audit_report.md`、`correction_miss_log.md`、`patch_manifest.json` |

**存疑项自动汇总**：`corrections/*.json` 中 `type=存疑` 或 `reason` 以"存疑"开头的补丁，自动提取成表（来源 / phys / 原文 / 存疑说明），列入第三节。

**数字口径统一**：补丁总数、active/deleted 计数与 `patch_manifest.json` 最终态一致；新增或撤销补丁后须回写本节数字，不得前后不一致。

## 6.3 `04_改错留痕.md` 规范

> 04 是这本书的账本：每个字为什么改、第几页改了什么、撤销了哪些。**拿着 03 的某一页，必须能在 04 里查到这一页发生过什么。**

**生成方式：台账主源 + diff 兜底**（由 `gen_correction_ledger.py` 产出）
- **主源**：从 `patch_manifest` 中 `status=active` 的补丁逐条取 `old/new/类型/依据/来源`。
- **兜底**：`diff(最终 03 干净文本, 原始 pristine 文本)` 发现台账遗漏的改处并报警——**用 diff 找漏，不用 diff 生成清单**（纯 diff 会把剥书眉 / 加锚 / 结构清洗当"改错"）。
- **只列真改过的**：`old` 在底本 0 命中的预防性登记不入 §一——那不是"改了几处"，是"准备了但没用上"，会把真正发生过的改动淹没。

**§一 通改总清单**：按类型分组（形近字 / 义校 / 专名 / 书名号 / 数字标点…），合并同 `old→new`，标注命中页数与补丁来源文件；同一 `old→new` 只出现一次。

**§二 逐页明细**：按 `<<<PAGE phys=N book=M>>>` 排序，每页列该页所有改动：`原OCR「X」→ 改「Y」（类型 + 依据 + 补丁来源）`。**这一节是"翻到某页查改了什么"的主体，不压缩、不抽稀。**

**§三 一致性自校验**：
- §一所列 `old` 在 03 干净正文残留 = 0；
- §一所列 `new` 在 03 干净正文命中 > 0；
- 条数 = active 补丁条数 + diff 发现数；
- diff 发现的"台账遗漏改处"单独列出并报警；
- 结论：通过 / 未通过（未通过列差异）。

**§四 撤销与人工修订**：两类各一行一条
- 经核实撤销的补丁：`phys / 原补丁 old→new / 撤销理由 / 核实方式`；
- 修订路径下的人工定点修订：`phys / 原文 / 改为 / 理由`。

> 撤销也是改动，与改错同记一本账，才能"翻到某页就查到这页发生过什么"。

**§五 交付指纹**（assemble 定稿前追加，`pipeline_assemble.py` / `assemble_epub.py` 同构）：
- 记 00/01/02/03 的 sha256，格式 `00=sha256:<64hex>；01=…；…`；
- **为什么用哈希不用 mtime**：work 与交付目录常在 OneDrive 内，同步会刷新 mtime，mtime 判据认不出「内容被换过」；
- 指纹用于**确认交付件与 04 记录同源**。修订路径下改了 03，就在 §四 登记并更新指纹——指纹是留痕工具，不是拦下改动的闸。

**corrections 台账完整性保护（patch_manifest.json）**：
- `.work` 被 gitignore，git 查不到删除史。台账全历史可追溯，不依赖 git。
- **自动索引**：`gen_patch_manifest.py` 扫描 `corrections/*.json` 生成 `patch_manifest.json`（含 `status` 字段）；不人工维护第二份真相源。
- **删除登记**：删除走「核实 → 04 §四 登记 → 标 `deleted`」三步，不物理删；assemble / 闸B 只处理 `active`。

## 6.4 图版嵌入工具链（PDF + EPUB 两条路径）

**整页图版嵌入**（`06_embed_pdf_figures.py` / `06b_embed_epub_figures.py` / `06c_embed_epub_slice_figs.py`）：EPUB 从 zip 解内嵌 `<img>`、PDF 从图版页渲染提图。两工具均**纯插入、零改写**——不动原页任何文字，只在 03 对应位置插图片引用行；写盘统一 LF、自动备份、幂等。

**正文内嵌图版**（`07_probe_page_figures.py --pdf <pdf> --out <dir>` → `07e_figcrop_refine.py --pdf <pdf> --out <dir>` → `07b_classify_figures.py --probe <json> --figdir <dir> --out <json>` → `07c_embed_figures.py --pdf <pdf> --md <03> --probe <json> --classify <json> [--apply]`）：补整页图版覆盖不到的另一半——图与正文同页、图幅只占页面一块，且**无图号也能自动找图**。整页扫描型 PDF 尤其需要。

> 路径三（PaddleOCR 三件套）跳过本节工具链——book_ocr 三件套本身已含图版，复用已嵌裁图即可。

**技术实现细节**：补丁施加器匹配与让位机制（`apply_corrections_core`）、共享口径单一真相源（`_fig_common.py`）见对应脚本注释。
